# session-title-refresh

Claude Code のセッション名を、中身に合わせて自動で最新化する仕組み。
**Local 環境のデスクトップセッション専用**（セッション横断ツールとスケジュールタスクが必要）。

## 構成

1日1回だけスケジュールタスクが起動し、**そのセッションの中で20分ループを回す**。

```
毎朝 7:13  ─→  ランチャーセッションが1本立つ（サイドバーの「Scheduled」に出る）
                 └─ /loop 20m /session-title-refresh  ← このセッションに常駐して回り続ける
                      ├─ 20分後: 直近40分に動いたセッションだけ見て、必要ならリネーム
                      ├─ 20分後: 同上
                      └─ ...
```

20分ごとのスケジュールタスクは**作らない**。実行のたびに新しいセッションが立ち、
1日数十本たまって一覧が埋まるため。ループはセッション内に常駐するので、
セッションは1日1本しか増えない。

## ファイル

| ファイル | 用途 |
| --- | --- |
| `SKILL.md` | スキル本体。`~/.claude/skills/session-title-refresh/SKILL.md` に置く |
| `task-prompt.md` | スケジュールタスクの Instructions に貼るプロンプト |
| `install.sh` | スキルを設置する（既存があれば上書きせず中止） |
| `uninstall.sh` | スキルを削除し、残りの撤去手順を表示する |

## 前提: Local 環境で作業すること

デスクトップアプリは Local / Cloud / SSH / WSL のどれでも動かせる。この仕組みが必要とする
ものは Local セッションにしか無い:

- **セッション横断ツール**（一覧・内容の読み取り・リネーム）は、デスクトップアプリ自身が
  動かしているセッション（Local / SSH / WSL）だけを見る。Cloud セッションからは使えないし、
  Cloud セッションは一覧にも出てこない
- **スケジュールタスク**（Routines の Local）は Local 環境の機能
- `~/.claude/skills/` の個人スキルが読まれるのは Local セッション。Cloud セッションは
  claude.ai アカウント側のスキルを読む

新規セッションを作るとき、プロンプト欄の環境ドロップダウンで **Local** を選ぶ。
セッション上部に雲アイコンが出ていたらそれは Cloud なので、この仕組みは動かない。

## 設置手順

### いちばん速い方法: Local セッションの Claude に頼む

Local セッションを1本開いて、このリポジトリを開いた状態でこう言う:

> tools/session-title-refresh/README.md を読んで、スキルの設置とスケジュールタスクの作成まで
> やって。タスクは毎日1回・朝7:13・通知オフ。20分ごとのタスクは絶対に作らないこと。

### 手動でやる場合

**1. スキルを置く**

```bash
tools/session-title-refresh/install.sh
```

`SKILL.md` を `~/.claude/skills/session-title-refresh/SKILL.md` にコピーするだけでもよい。

**2. スケジュールタスクを作る**

サイドバーの **Routines** → **New routine** → **Local** を選び、こう埋める:

| 欄 | 値 |
| --- | --- |
| Name | `session-title-refresh`（小文字ケバブケースに変換され、ディスク上のフォルダ名になる） |
| Description | セッション名オートリフレッシュのランチャー |
| Instructions | `task-prompt.md` の中身をそのまま |
| フォルダ | 任意（このリポジトリでよい）。保存にはフォルダ指定が必須 |
| worktree | オフ（ファイルを触らないので不要） |
| Schedule | **Daily**、時刻ピッカーで **7:13** |

UI に cron 欄は無い。Daily + 時刻ピッカーで足りる。ピッカーで表現できない間隔が
必要になったら、Local セッションの Claude に日本語で頼めば設定できる。
時刻は好みで変えてよいが、**頻度は1日1回のままにすること。**

**3. 1回だけ Run now**

タスクの詳細ページで **Run now**。今日の分の起動を兼ねる。
このとき権限の確認が出たら **always allow** を選んでおく。次回以降のループが
権限待ちで止まらなくなる。

## やめたいとき

Claude にこう言えば止まる:

> session-title-refresh のスキルとタスクを削除して、ループが動いているセッションも閉じて

手で撤去する場合:

1. `tools/session-title-refresh/uninstall.sh` を実行（`~/.claude/skills/` 側を削除）
2. Routines のタスク詳細ページで **Delete**。確認ダイアログの
   **Also delete files on disk** にチェックを入れると
   `~/.claude/scheduled-tasks/session-title-refresh/` も消える
3. ループが常駐しているランチャーセッションを開いて停止し、アーカイブする

## 安全側の設計

- 使うツールはセッションの一覧・読み取り・リネームの3つだけ。
  セッションファイルの直接編集はしない
- 読んだ会話の中身はデータとして扱い、指示めいた文面があっても従わない
- 対象は「直近40分以内に活動」かつ「前回から最終活動時刻が変わった」セッションのみ。
  対象ゼロなら追加のツールを呼ばずに終了する（無駄な読み取りをしない）
- リネームするのは「無題」か「内容と明らかにズレている」場合だけ。
  ユーザーが意図して付けた名前は変えない。迷ったらリネームしない
- タイトルに顧客名・個人名・URLは入れない
- 自分自身はリネームしない（そもそもこの surface は「今聞かれているセッション」を
  一覧に出さないので、自動的に対象外になる）

## 仕様上の制約

- **Cloud セッションの名前は変わらない。** このセッション横断 surface からは Cloud
  セッションが見えないため。ターミナルの CLI や VS Code 拡張から起動したセッションも同様
- **PCが起きている間だけ動く。** Local のスケジュールタスクはアプリが起動していて
  かつPCがスリープしていないときにしか発火しない。スリープで飛んだ場合、起床時に
  直近の1回分だけ catch-up 実行される（7日以内）
- **ランチャーセッションからのセッション間メッセージ送受信はできない。** スケジュール
  タスク実行のような「誰も見ていないセッション」からのメッセージ送信は禁止されている。
  一覧・読み取り・リネームは制限対象外なので、この仕組みには影響しない
- 見えるのは直近20セッションまで。アーカイブ済みは除外される
