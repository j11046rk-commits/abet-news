# しっぽり亭 予約管理システム（shippori-reserve）

新居浜の居酒屋「しっぽり亭」の、**店舗予約を1つのダッシュボードに集約して管理する**ためのシステム。
現在は **設計フェーズ**。このディレクトリにはまだアプリのコードはなく、設計ドキュメントだけが入っている。

## ひとことで言うと

> ホームページ・Instagram DM・公式LINE・電話・オーナー直通。
> **バラバラに入ってくる予約を、スタッフのiPhoneの中の1画面にまとめる。**

## 前提（依頼内容の要約）

- **業態は日単位で2つ**。
  - 通常営業（しっぽり営業）＝**席ごと**の予約管理
  - イベント営業（ビアホール営業）＝相席前提。席は管理せず**定員（総受け入れ人数）だけ**を管理
- **流入経路5つ**を集約：HP予約フォーム／Instagram DM／公式LINE／電話／オーナー3名への直接連絡
- 登録・編集は**ログインしたスタッフのみ**。ロールは**後から細かく分けられる**構造にする
- **席割り当てルール**を曜日・繁忙日ごとに設定でき、**スタッフ判断の上書き（オーバーライド）**を残す
- **PWA**。iPhoneの「ホーム画面に追加」でアプリのように使える
- 既存の[しっぽり亭ホームページ](https://shipporitei.jp/)（`site/`）と同じドメイン／プロジェクト配下に組み込む

## 現状構成の調査結果（ここが設計の出発点）

| 対象 | 現状 |
|---|---|

| ホスティング | **GitHub Pages**（`.github/workflows/pages-preview.yml` でビルド&デプロイ）／独自ドメイン `shipporitei.jp` |
| 既存の「ダッシュボード」 | `site/src/pages/dashboard.astro` — GA4のアクセス解析を**ビルド時に暗号化して静的配信**し、共通パスワードで復号する仕組み（`scripts/encrypt-dashboard.mjs`） |
| 既存の予約導線 | `site/src/components/Reservation.astro` — 電話 / 公式LINE / Instagram DM への**リンクのみ**。予約フォームもDBも無い |
| 席 | カウンター10席 ／ 半個室テーブル6名×3 ／ 掘りごたつ個室8名×1 ＝ **36席**（貸切25名〜・団体最大36名） |
| 営業時間 | 日〜木 18:00〜24:00（L.O.23:30）／金・土 18:00〜25:00（L.O.24:30）／**火曜定休** |
| 社内の先行事例 | `the-oldman/` — **Next.js 15 + Supabase + Vercel** のログイン制PWA。同じリポジトリ・同じ運営者・稼働中 |

- 予約の流入元「**オーナー直接**」では、上のオーナー3名から誰経由かを選ぶ（後から個別に集計できる）。
- 権限はロールごとにDBの表で持つので、**「一般スタッフにも◯◯を許可」は行を1つ足すだけ**。コード変更不要。
- 詳細 → [01-architecture.md §1-6](docs/01-architecture.md#1-6-権限モデル後から細かく分けられる構造) / [06-roadmap.md](docs/06-roadmap.md#初期アカウントphase-1-4)

**重要な結論**：既存サイトは静的サイト（サーバーもDBも無い）なので、そこに予約管理を足すことはできない。
また `dashboard.astro` の「共通パスワードで復号」方式は、**お客様の氏名・電話番号を扱う予約管理には使えない**
（誰が見たか記録できず、スタッフ個別の停止もできず、暗号化済みデータが誰でもダウンロードできる）。
→ **アプリは別プロジェクトとして作り、既存サイトとはリンクとAPIで繋ぐ**のが正解。詳細は [05-stack.md](docs/05-stack.md)。
