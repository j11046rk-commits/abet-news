# 物販・催事を「第2の柱」として指標化する

## 0. 先に結論

**2026-07-26 は「売れた日」ではなく「店内が落ちた日」でもある。**

| | 金額 | 意味 |
|---|---|---|
| その日の総額 | 680,830円 | エアレジから `sales_daily.actual_yen` に1行で入っている |
| うち物販（太巻き） | 約623,000円 | いま、システム上は区別がつかない |
| **差し引き＝店内飲食** | **約57,830円** | |
| 日曜の平均日商 | 84,224円 | |
| **店内の増減** | **▲約26,000円（平年の69%）** | ← 混ぜている限り永久に見えない |

その日は「通常の5日分」を稼いだ日であると同時に、**店内飲食が平年の7割に落ちた日**でもあります。厨房の人手が太巻きに取られたのか、常連が「今日は混む」と敬遠したのか、単に日曜の下振れか。原因はまだ分かりませんが、**切り分けない限り「原因を問う」ことすらできない**。これが本件の核心です。

そしてもう一つ。**この1日が7月の月商に与えたインパクトは、7月の月間目標2,750,000円に対して約22.7%**。前年比を「1営業日あたり平均」で見ている今の分析（`02_readings.sql` の D）だと、7月の1日あたりが約2万円押し上げられ、**前年比85%の店が103%に見えます**。2026年前半82〜86%という不調のトレンドが、たった1日で消える。これは分析の破綻です。

## 1. 飲食店における物販・テイクアウト・催事の位置づけ

### 1-1. 市場としての大きさ（＝これは「例外」ではなく「産業」）

- 外食業態のテイクアウト市場は2024/3〜2025/2で**2兆1,075億円、コロナ前比+24%**（[Circana Japan](https://www.npdjapan.com/press-releases/pr_20250421/)）。外食産業全体が約35.7兆円（[富士経済](https://www.fuji-keizai.co.jp/press/detail.html?cid=25077&la=ja&la=en)）なので、**外食店が店外で売る売上は全体の6%前後**。
- 中食市場は11兆円規模に到達し、2025年の外食・中食市場は22.84兆円で調査開始以来最高（[日本食糧新聞](https://news.nissyoku.co.jp/restaurant/hamada20260105051323722)、[CREX](https://crexgroup.com/ja/data/market-data/ready-to-eat-market-size/)）。

**正直に言うと、「個人居酒屋の物販比率はX%が適正」という業界標準は存在しません。**探しましたが、確立した数字はない。だから外から借りた目標ではなく、**しっぽり亭自身の数字から置くべき**です（後述6章で具体案）。

### 1-2. 利益率が根本的に違う

| | 店内飲食 | 物販・催事 |
|---|---|---|
| 原価率 | 一般に30%前後が目安。ただし主要外食100社の平均は**37.5%まで上昇**（[飲食店ドットコム](https://www.inshokuten.com/supplier/knowledge/detail/71)） | **高くなりやすい**。恵方巻は一説に売上原価率80%程度との推計もある（[個人ブログの試算](https://www.tyoshiki.com/entry/2022/08/03/074813)・出典の質は高くないが「高い」方向は各所で一致） |
| なぜ高いか | ドリンクで原価を薄められる | **ドリンクが付かない**（居酒屋の利益源が丸ごと消える）／値ごろ感が要る／容器代／売れ残りが全損 |
| 家賃・光熱費 | 売上に紐づく | **追加ゼロ**（同じ厨房・同じ店） |
| 人件費 | 接客が必要 | 仕込みのみ。接客時間はほぼゼロ |

**ここが一番大事な理屈です。** 原価率だけ見ると物販は「悪い商売」に見える。しかし家賃・光熱費が追加でかからず、接客人件費もほぼ不要なので、**「その日に追加で生んだ粗利額」で見ると強い**。

具体的に、7/26のケースを2つのシナリオで:

| | 売上 | 原価率 | 粗利額 |
|---|---|---|---|
| 太巻き（原価率50%と仮定） | 623,000円 | 50% | **311,500円** |
| 太巻き（原価率65%と仮定） | 623,000円 | 65% | **218,050円** |
| 参考: 通常営業の日曜1日 | 84,224円 | 30% | 58,957円 |

**原価率65%という「悪い」商売でも、粗利額は通常営業3.7日分。** だから率で判断してはいけない。見るべきは **限界利益額 ÷ 追加で使った仕込み時間**（＝時給いくらの仕事だったか）です。

> ⚠️ **2027年のうなぎには警告があります。** 2026年はシラスウナギが豊漁で、かば焼き小売価格は前年比1割安（[日経](https://www.nikkei.com/article/DGXZQOUB201RM0Q6A720C2000000/)、[KSB](https://news.ksb.co.jp/article/16662851)）。**つまり7/26の好成績は「安い年」に助けられた可能性がある。**市場では養殖量の抑制とエサ代転嫁で「手ごろさは来夏までは続かない」との見方が多い。2027年の丑の日は**原価が上がる前提で価格を決める**必要があります。だからこそ今年の原価を記録しておかないと来年の値付けができない。

### 1-3. 別管理すべき理由（3つ）

1. **経営判断の単位が違う** — 売上は経営判断の方向性を左右する指標なので、販売形態別に細分化して管理すべき、と明示されています（[NEC モバイルPOS](https://jpn.nec.com/mobile-pos/column/column0078/index.html)）。POSの部門コードで店内飲食/テイクアウト/デリバリーを分けるのは業界の標準的なやり方。
2. **成功の定義が違う** — 店内は「客数×客単価×回転」、物販は「作った数×完売率×単価」。改善レバーが一つも共通していない。
3. **失敗のコストが違う** — 店内は暇な日でも損失は機会損失だけ。物販は**作った分が売れ残れば現金がそのまま消える**。だからリスク管理が必須で、それは別の指標でしか測れない。

## 2. 居酒屋が仕掛けられる年間催事カレンダー

**型の定義**
- **【予約型】** 事前予約を取って、その数だけ作る。ロスがほぼゼロ。売上上限は予約獲得力で決まる
- **【当日型】** 見込みで作って当日売る。上振れが取れるがロス責任を負う
- **【併用型】** 予約を基礎数量にして、上乗せ分だけ当日売る ← **推奨。7/26はおそらくこれ**

**なぜ予約型が正義か**: 農林水産省が食品ロス削減推進法を踏まえ、恵方巻など季節食品の**予約販売を小売業者に呼びかけている**（[農水省](https://www.maff.go.jp/j/shokusan/recycle/syoku_loss/kisetsusyokuhin.html)、[J-Net21](https://j-net21.smrj.go.jp/news/rh2rue0000002en4.html)）。事前に作る量が分かっていれば捨てる量が減る。個人店にとっては倫理の話である以上に**キャッシュの話**です。

### 2-3. カレンダーから出てくる原則

**物販は谷曜日（水・木）と、店内が弱い月（10月）に置く。金土と12月にはぶつけない。**

理由: 物販は席を消費しないが、**厨房の手は消費する**。金土は厨房が既に埋まっているので、そこで500本巻けば店内サービスが落ちる（＝7/26で起きた可能性のあること）。水木は厨房に余力がある。**同じ商品でも、置く曜日で利益が変わる。**

**2027年は運がいい年です。** 一の丑が水曜、二の丑が月曜、節分が水曜、ひな祭りが水曜 — 主要な物販催事が軒並み谷曜日に落ちている。逆にクリスマスイヴが金曜なので、ここだけは予約型に絞る。

## 3. 切り分けないと何が起きるか（既存クエリで具体的に）

`/home/user/abet-news/shippori-reserve/supabase/analysis/02_readings.sql` は既に「1日の売上は外れ値がすぐ効くので平均は当てにならない」と書かれ、**中央値で守りを固めている良い設計**です。だからこそ問題がはっきりします。

| クエリ | 何が壊れるか |
|---|---|
| **D. 前年同月比（1営業日あたり平均）** | 🔴 **致命的。** 62.3万 ÷ 26営業日 ≒ **+2.4万円/日**。7月の前年比が約20ポイント跳ね上がる。**「2026年前半は82〜86%」という一番大事な事実が、7月だけ嘘になる** |
| **A. 曜日の型** | 平均列が日曜だけ押し上げられる。中央値は無事だが、中央値と平均が乖離して読み手が混乱する |
| **K. MAD外れ値検出** | ⚠️ 7/26を必ず検出する。**検出はする。しかし「なぜ」を書く欄が無い。** 来年これを見た人は理由を思い出せない |
| **L. 月末着地見込み** | 🔴 曜日中央値で残りを埋める作り。**催事予定日を含む月は着地予測が数十万円ずれる**。逆に、切り分ければ「店内の着地見込み + 催事の予定額」と足し算できて精度が上がる |
| **J. 目標の置き直し** | 🔴 実績中央値を重みに使うので、催事日が混ざると**その曜日の目標が恒久的に吊り上がる**。来年その曜日が毎週未達になる |
| **H/I. 目標達成率** | 7/26の達成率は600%超。中央値も平均も壊れる |

### さらに、システム独自の問題

`/home/user/abet-news/shippori-reserve/src/app/(app)/sales/page.tsx` には**紙吹雪・ストリーク・貢献⭐・道のりゲージ**という達成の演出が入っています。ここに催事を混ぜると:

- 1日で月間目標の23%が達成される → **道のりゲージが意味を失う**
- その1日の後、通常営業の達成が全部かすむ → **スタッフのモチベーション設計が壊れる**
- ストリークが「太巻きの日」だけで繋がる → **日々の努力を測る指標でなくなる**

**催事は別のメダルにすべきです。**「今日は太巻きで◯本売った」は、店内の目標達成とは別の祝い方をする。

> **【対応済み 2026-08】** 日毎の判定（紙吹雪・ストリーク・貢献⭐・グリッドの金色）は
> 店内の売上だけで見るようにした。道のりゲージと月間達成は物販込みの合計のまま。
> 物販は「今月の物販」カードに別枠で出す。
> なお **⭐と連続達成は店内だけで判定する**ので、太巻きの日に店内が目標割れすると
> ⭐が付かず連続も切れる。これは店主の指示から出る帰結だが、働いた人が報われない
> という別の問題があるので、運用してみて気になるようなら扱いを見直す。

### 逆に、切り分けると得られるもの

- 「2026年は前年比85%だが、**物販を含めた総売上では92%**」という**2本立ての正しい語り**ができる
- 「店内は落ちているが、**別の柱が育っている**」という経営判断ができる
- 7/26の店内▲2.6万が見えて、**来年のオペレーション改善につながる**

## 4. 特需の成否を測る指標

店内のKPI（客数・客単価・回転）は1つも使えません。物販専用の6つを提案します。

### 主指標（必ず取る4つ）

| # | 指標 | 計算 | 7/26の推定値 | 判断基準 |
|---|---|---|---|---|
| **1** | **粗利額** | 売上 − 仕込み原価 | 22〜31万円（原価率50-65%と仮定） | ⭐**最重要。率ではなく額。**「通常営業の何日分か」で語る |
| **2** | **完売率** | 売れた数 ÷ 作った数 | 不明（記録なし） | **95%以上が目標。** 下回るとロスが粗利を食う |
| **3** | **予約比率** | 予約分 ÷ 売れた数 | 不明 | **70%以上を目指す。**高いほど作る数が読めてロスが消える |
| **4** | **カニバリ差分** | その日の店内売上 − 同曜日の中央値 | **▲約26,000円** | ⭐**7/26で唯一計算できた指標であり、唯一の赤信号** |

### 補助指標（余裕があれば）

| # | 指標 | 計算 | なぜ |
|---|---|---|---|
| **5** | **仕込み時給** | 粗利額 ÷ 仕込み総時間 | 「その日1日で5日分」でも、3日間徹夜なら割に合わない。**個人店では労働時間が最大の制約** |
| **6** | **新規獲得** | 催事の予約電話番号のうち、過去の予約に無い番号／その番号が後日来店した数 | ⭐**追加コストゼロで測れる**（後述）。物販の本当の価値は「一見客に店を知ってもらう」ことかもしれない |

### 指標6が特に重要な理由

62.3万円を「1日の売上」として見ると単発の花火です。しかし**その日に太巻きを買った人のうち、何人が後日 飲みに来たか**が測れれば、物販は**集客チャネル**として評価できる。

`/home/user/abet-news/shippori-reserve/supabase/migrations/0004_reservations.sql` の `reservations` には既に **`phone`（電話番号）と `source`（流入元）** があります。**催事の予約も reservations に入れておけば、電話番号の突合だけで「催事で初めて接点を持った人が、後日店内予約に現れたか」が追える。** 追加のテーブルもコードも要りません。これが物販を予約テーブルに載せる最大の理由です。

## 5. システムへの最小の追加

### 現状

```sql
-- /home/user/abet-news/shippori-reserve/supabase/migrations/0018_sales.sql
create table sales_daily (
  biz_date   date primary key,
  target_yen integer,
  actual_yen integer,   -- ← 店内も物販も全部ここに混ざっている
  ...
);
```

エアレジからの取り込みは日単位の合計しか返さないので、**「オーナーが催事の日だけ数字を1つ入れる」以外に切り分ける方法がありません。**そこを最小コストにするのが設計目標です。

### 提案: 追加は1テーブル＋1カラム、入力は「催事の日だけ」

```sql
-- 0030_event_sales.sql

-- ① sales_daily に「うち物販」を1列だけ足す
--    この1列だけで、既存の全分析が「店内だけ」で読み直せるようになる
alter table sales_daily add column if not exists retail_yen integer
  check (retail_yen is null or retail_yen >= 0);

comment on column sales_daily.retail_yen is
  'actual_yen のうち、物販・催事・テイクアウトの分。null は「催事なし」。
   店内飲食 = actual_yen - coalesce(retail_yen, 0)';

-- ② 催事の中身は別テーブル（1催事1行。年に5〜8行しか増えない）
create table if not exists sales_event (
  biz_date      date not null references sales_daily(biz_date),
  code          text not null,      -- 'unagi_futomaki' 'ehomaki' 'osechi' …
  name          text not null,      -- 「うなぎの太巻き」
  unit_price    integer,            -- 1本あたりの売価
  qty_reserved  integer,            -- 予約で入った数
  qty_made      integer,            -- 実際に作った数
  qty_sold      integer,            -- 売れた数
  cost_yen      integer,            -- 仕込みにかかった材料費（分かる範囲で）
  prep_hours    numeric(4,1),       -- 仕込みに使った延べ時間
  note          text,               -- 「うなぎが安い年だった」「雨」など、来年の自分への手紙
  primary key (biz_date, code)
);
```

**入力負荷**: 催事の日の夜に、スマホで**5つの数字**（売れた金額・作った数・売れた数・予約数・材料費）。年に5〜8回だけ。

**なぜ `retail_yen` を `sales_daily` に持たせるか**: `sales_event` から毎回 join させると既存の全クエリを書き換えることになります。1カラムなら `v_sales_day` に2行足すだけで済む。

### ③ `v_sales_day` に3列足す（既存クエリの書き換えは `actual_yen` → `instore_yen` の置換のみ）

```sql
-- /home/user/abet-news/shippori-reserve/supabase/analysis/01_v_sales_day.sql に追加
  s.actual_yen,
  coalesce(s.retail_yen, 0)                          as retail_yen,
  s.actual_yen - coalesce(s.retail_yen, 0)           as instore_yen,  -- ★通常分析はこれを見る
  (coalesce(s.retail_yen, 0) > 0)                    as is_event_sale,
```

**運用ルール（これが本体）**
- 通常営業の分析（A〜L 全部）は **`instore_yen`** を見る
- 前年比・目標・着地見込み・曜日中央値 → すべて `instore_yen`
- 催事は `sales_event` から別立てで集計する
- ~~**目標 `target_yen` / `sales_monthly` は「店内の目標」と再定義する。**催事はボーナス扱い~~
  → **実装では逆にした（店主判断 2026-08）。** 月間目標 `sales_monthly` は物販を含む
  合計に対する目標のまま。日毎の目標 `target_yen` だけが店内に対する目標になる。
  店主の言葉は「月間の売上目標には計上したいから、日毎の売上からは外して、別枠で表記しよう」

### ④ 画面（オーナーは非エンジニア・スマホ）

**追加は2箇所だけ:**

1. **日別画面** `/home/user/abet-news/shippori-reserve/src/app/(app)/day/[date]/page.tsx` に「今日は催事だった」トグル。ONで5つの入力欄が出る。OFFなら何も変わらない
2. **売上画面** `/home/user/abet-news/shippori-reserve/src/app/(app)/sales/page.tsx` の日商表示を **「店内 57,830円 ＋ 催事 623,000円」の2行表示**に。合計は今まで通り出す

**ゲーミフィケーションの分離**: 紙吹雪・ストリーク・道のりゲージは `instore_yen` で判定。催事は**別の演出（「催事メダル」）**にする。日々の達成が催事に食われないように。

### ⑤ 予約側（コード追加ほぼゼロ、価値は最大）

`reservations.source` に **`'takeout'`（持ち帰り）** を1つ足す。催事の予約電話を全部ここに入れれば:
- 予約数がリアルタイムで見える → **作る数が締切日に確定する**（完売率とロスが直接改善する）
- 電話番号が残る → **指標6（新規獲得・リピート）が後から測れる**
- 既存の予約一覧・絞り込みがそのまま使える

**席は消費しないので、席の埋まり判定からは除外**する必要があります（そこだけ実装注意）。

### ⑥ 外れ値クエリに「理由」を残す

`02_readings.sql` の K（MAD外れ値）は 7/26 を確実に検出しますが、理由が残らない。`sales_event.note` を join して**「検出された飛び値には必ず名前がついている」状態**にしてください。名前のない飛び値だけが調査対象になる ── これが正しい形です。

## まとめ

**やるべきことは1つに集約されます: `retail_yen` という整数カラムを1本足すこと。**

これだけで、
- 前年比82〜86%という**本当の姿が7月以降も守られる**
- 7/26の店内▲2.6万という**カニバリの存在が可視化される**
- 「店内は落ちているが、別の柱がある」という**2本立ての正しい経営の語り**ができる
- 来年の催事の**成否が数字で判断できる**

いま何もしなければ、2026年7月は「回復した月」として記録に残り、その誤解の上に2027年の目標が置かれます。**混ぜて記録することのコストは、集計の不正確さではなく、判断の誤りです。**
