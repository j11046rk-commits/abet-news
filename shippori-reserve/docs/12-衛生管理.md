# 衛生管理（HACCPの考え方を取り入れた衛生管理）

店長会議（2026-11-04）で決めた「衛生管理表を予約管理システムの中で付ける」の実装。
小規模な一般飲食店向け手引書の流れ（計画 → 周知 → 実施・記録 → 振り返り・見直し）をこの中で回す。

> この機能で作るのは書類と記録です。「HACCP認証」や「保健所の検査に合格」を示すものではありません。
> 画面にもそのように書いてあります。

## 作業量は最低限（店主指定 2026-11-04）

- 毎日の記録は **営業終了時の1回** にまとめる（項目・冷蔵庫とも既定は1日1回）。冷蔵庫・冷凍庫1台ずつなら1日9回のタップ・約1分
- 「⑤厨房・廃棄物・害虫」（店で足した項目）・仕込みごとの温度記録・週の確認は **既定で「なし」**。必要になったら計画やメニューごとにオンにする
- 計画で必須なのは：店舗名・食品衛生責任者・計画作成者・適用開始日、各項目のいつ／どのように／問題があったとき、冷蔵庫の温度基準、
  メニューの料理名・グループ・提供のしかた・確認方法。担当者・危害要因・頻度・保存方法などは任意
- 温度の入力は SwitchBot 防水温湿度計＋ハブでの自動取り込みを検討中（未実装）

## 何に基づいているか（混ぜない）

| 区分 | 中身 | 画面での出し方 |
|---|---|---|
| 法令上の義務 | 食品衛生法 第51条、施行規則 第66条の2・別表第17（一般衛生管理）・別表第18（計画・周知・記録・振り返り） | 計画の先頭「法令で求められていること」 |
| 手引書の項目・例 | 一般衛生管理の①〜④、第1〜第3グループ、確認方法の例 | 各項目に「手引書の項目（方法は手引書の例をもとに店舗で決める）」 |
| 店舗独自 | ⑤厨房・廃棄物・害虫対策、各基準値、使用期限 | 「店舗で追加した項目」／責任者が入れた値 |
| 設定候補 | 冷蔵10℃・冷凍−15℃・加熱75℃1分・二枚貝85〜90℃90秒・冷却30分20℃／60分10℃・高温保管65℃・アニサキス−20℃24時間 など | 出典つきで表示。「この候補を使う」を押したときだけ計画に入る |

**保存できる日数（使用期限）は候補を出さない。** 店で決めて入れる。室温でのおばんざい陳列は初期設定にしない。

## 決めごと（DB が守る）

- 承認した計画は書き換え・削除できない。変えるときは新しい版（下書き → オーナーが確定）。記録は当時の版に結び付く
- 記録者・修正者・承認者・確認者は `auth.uid()` から入る（画面から偽れない）
- 記録を直すには理由が要る。直す前と後は `haccp_revisions` に残る。最初の「問題あり」（`first_result`・`first_ng_at`）は消えない
- 過去日の記録は `entered_late`。実施日時（`measured_at`）と入力日時（`recorded_at`）は別の列
- 未入力は「行が無い」。該当なし（`na`）・休業（営業日の設定）と区別する。既定で良好を入れない・前日をコピーしない
- 記録は消せない（削除の方針なし）。自動で消す仕組みも無い（1年以上の保存を想定）
- 営業日は日本時間・朝4時まで前日（`haccp_biz_today()`／`todayBizDate()`）

権限（`role_permissions`）：`haccp.record` オーナー・店長・スタッフ／`haccp.manage` オーナー・店長／`haccp.approve` オーナー。事務・閲覧のみは衛生管理を見られない。

バックアップ：`/api/cron/backup` の対象に haccp_* の9表を追加（店主のMacの週次バックアップで控えが取られる）。

## 店で入れる・確かめること（未設定のままでは確定できない）

1. 食品衛生責任者の氏名、計画作成者、適用開始日
2. 一般衛生管理①〜④の確認方法・問題があったときの対応（たたき台を店のやり方に直す。「誰が」は任意）
3. 冷蔵庫・冷凍庫の台数・名前・基準温度・測るタイミング
4. 重要管理のメニュー（実際に出している料理を、料理名ではなく調理工程で第1〜第3グループに分ける）
   - 危害要因、管理基準、確認方法・頻度、基準を外れたときの対応
   - 第3グループ（作り置きのおばんざい）：保存方法と**店で決めた使用期限**
   - 刺身など生食用魚介類：アニサキス対策の方法／二枚貝：85〜90℃90秒の基準／低温調理：条件の根拠
6. 確定後：スタッフへの周知（日付・方法）を記録し、各自が「読みました」を押す
