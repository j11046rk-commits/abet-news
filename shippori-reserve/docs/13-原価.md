# 原価（仕入・棚卸・ロス）

店主の要望（2026-11-05）「原価率削減システムは今の店舗管理システムの中に入れたい」の実装。
税理士の8月報告で原価率は 34.5%（前期 41.2%）。ただし消耗品費が 229,127円（売上の6.8%）に跳ねていて、
足すと約41.3%。月次の棚卸はまだしていない。日野さんの資料（原価管理の考え方）も参考にした。

## 場所と権限

- 売上タブ → 右上の **「原価」**（`/sales/cost`）。棚卸（毎週日曜）は `/sales/cost/stock`
- 見る・入れる：オーナー・店長・事務（`cost.read` / `cost.write`）。スタッフ・閲覧のみには出ない
- 給与・人件費は一切扱わない

## 物差し

```
原価率 ＝（始めの在庫 ＋ その間の仕入 − 終わりの在庫）÷ その間の売上
```

棚卸は **毎週日曜**（店主指示 2026-11-09「日曜が暇なことが多いから、毎週日曜に棚卸をする仕組みにしたい」）。
原価率は **確定した棚卸と次の確定した棚卸の間**（ふだん1週間）ごとに出す。
月の数字は、その月に終わった区間をつなげたもの（例：11/2〜11/29）。暦の1日〜末日とは少しずれるので、期間をそのまま画面に書く。
決算の月だけは月末にも数えれば、その日で区切れる（棚卸はどの日でも何回でも入れられる）。

- 仕入も売上も **税抜**（税理士の月次報告と同じ）。食材は8%、店内の売上は10%なので、税込どうしで割ると約2ポイント低く出る
- 売上の税抜：店内（合計−物販）÷1.1 ＋ 物販÷1.08。売上は今の売上タブの実績（エアレジ）をそのまま使う
- 原価に入れるのは **食材＋酒・飲料**。消耗品は別に数え、「消耗品も入れると○%」として並べる
- **確定した棚卸が2回そろうまで原価率は出さない**（「まだ出せません」）。
  代わりに「仕入÷売上」を **目安** として出す（月の目安、今週の目安）。在庫の増減を無視した数字を原価率と呼ぶと、仕入れが多い週に誤った警報になる
- 使うのは **確定した** 棚卸だけ。下書きは飛ばす
- 月締めの請求書は、対象の期間（例 10/21〜11/20）が読めていれば **日割り** にする。締め日の週だけ原価率が跳ねないように

## 入れるもの（3つだけ）

### 1. 仕入：店長が毎日撮るだけ → 毎朝 Claude がまとめて読む → 写真と見比べて「確認した」

店主指示（2026-11-06）「APIは消費したくない。店長が毎日撮って、それを取りに行って、サブスクのClaudeで解析する」。
アプリは Claude API を一切呼ばない（`@anthropic-ai/sdk` も外した）。

```
撮る（店長・毎日／過去の書類は「保存した写真から選ぶ」でまとめて）
  → 読み取り待ち（pending）… 撮った日の月に並ぶ。原価にはまだ入らない
  → 毎朝 5:13（日本時間）、Claude Code の定期実行（サブスクのセッション）が
     GET /api/cost/reader で一覧と写真を取り、読んで POST で返す
  → 未確認（unconfirmed）… 金額が入り、計上日の月へ移る。原価率には入る。AIの「確認してほしい点」も出る
  → 写真と見比べて「✓ 確認した」か「直す」→ 確認済み（confirmed）
```

- 書類の種類は3つ：**納品書**／**請求書（月締め）**／**レシート**（現金・カード）
- 決めごと：**納品書とレシートを毎日撮る。請求書は撮らない**（月初に紙で納品書と突き合わせるだけ）。
  納品書の無い月締めの業者だけ請求書を撮る。毎日撮れば、月の途中でも「今日までの仕入÷売上」がほぼ正しく出る
- 1枚の書類を「食材・酒飲料・消耗品・その他」に分けて税抜で持つ（スーパーのレシートは食材と消耗品が混ざるため）。
  税込で読んだ行は、読めた税率（8%/10%）か区分の税率で税抜に戻す
- 読めなかった写真は「（読み取れず）」＋理由で未確認に入る。直す画面で写真を見ながら手で入れる
- **二重の警告**（保存は止めない）：同じ業者の請求書と納品書・レシートが同じ月にある／同じ業者・同じ日・同じ金額が2件以上
- クレジットカードの明細は入れない（レシートと二重になる）。レシートが無い買い物を探すのに使う

読み取り口 `/api/cost/reader`（`src/app/api/cost/reader/route.ts`）：
- 守りは `x-api-key`。合言葉はオーナーが原価ページ下の「AIの読み取りの設定」で発行する。DB（`api_tokens`）にはハッシュだけを置き、平文は発行した1回だけ画面に出る
- 定期実行のセッションには、合言葉を Claude の環境の「認証情報」（yoyaku.shipporitei.jp・ヘッダ x-api-key）として持たせる。プロンプトには書かない
- 受け取る結果は形・種類・金額の範囲を全部検査する（`parseAiDoc`）。読み取り待ちでない行（人が先に入れた）は上書きしない

### 2. 毎週日曜の棚卸

- 「棚卸を始める」で **数える日**（初期値は直近の日曜）を選び「数え始める（営業中の暇なときでOK）」
  - 店主指示 2026-11-09「開店前・閉店後だと人件費が無駄になりすぎる。精度は少し落ちても営業中の暇な時に」（0070）
  - 営業中に数えた → その日（日曜）の営業までの在庫として扱う。数えたあとに出た料理のぶんだけずれるが、
    毎週だいたい同じ時間帯なら週ごとの比べ方は変わらず、ずれは翌週に持ち越されて打ち消し合う（月の合計は変わらない）
  - 開店前に数えた → 前の日（土曜）の営業まで／閉店後 → その日まで（「開店前・閉店後に数えるとき」を開くと選べる）
  - DB は「どの営業日の終わりまでの在庫か」（`as_of`）で持つ。数えた日・いつ数えたかはあとで変えられない（間違えたら下書きを消して作り直す）
- 品目（品名・単位・税抜の単価・食材か酒）を一度登録すれば、毎週は **数を入れるだけ**（前回の数も横に出る）
- **空欄＝数えていない（0とは別）**。0を入れれば0として数える
- 細かい調味料は「調味料まとめて（単位：円・単価1）」のように金額で1行にしてよい
- 「この数で確定する」で在庫額を固定。確定した棚卸の数は DB が直させない・消させない（直すときは「確定を外す」）
- 数えた時点の単価を行ごとに持つので、あとで単価を直しても過去の在庫額は動かない

### 3. ロス（捨てたもの）

- 日付・品・金額（仕入値の目安・税抜）・理由（期限切れ／作りすぎ／調理ミス／傷み・破損／その他）・写真（任意）
- 原価率の計算には足さない（捨てた分はすでに仕入に入っている）。何をどれだけ捨てたかを見て、仕込み量・発注量を直すための記録

## DB（0065_cost.sql・0066・0069）

| 表 | 中身 |
|---|---|
| `cost_purchases` | 書類1枚＝1行。状態（読み取り待ち／未確認／確認済み）・AIの確認メモ。計上日・業者・種類・区分ごとの税抜額・税込合計・請求期間・写真・AIで読んだか。作った人／直した人は DB が入れる |
| `cost_stock_items` | 棚卸の品目と今の単価 |
| `cost_stocktakes` | 棚卸（`as_of`＝この営業日の終わりまでの在庫・数えた日・営業中／開店前／閉店後・下書き／確定・確定時の在庫額）。0069 で月ごとから作り直し・0070 で営業中を追加 |
| `cost_stock_counts` | 棚卸×品目の数と、数えた時点の単価。確定した棚卸はトリガで書き換え・削除不可 |
| `cost_losses` | ロス |
| `api_tokens` | 外から来る機械の合言葉（ハッシュだけ）。画面からは読めない（0066） |

写真は非公開の置き場 `cost-photos`。表示は1時間だけ有効なURLをサーバーが作る。
毎日のバックアップ（`/api/cron/backup`）に5つの表を含めた。
