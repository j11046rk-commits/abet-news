# 2. 画面一覧

## 2-0. 前提：iPhoneの片手操作が基準

- 基準解像度 **375×667（iPhone SE）**。ここに収まらないものは設計が間違っている。
- 主要操作（予約を1件登録する／席を割り当てる／来店にする）は**親指の届く下半分**で完結させる。
- ナビゲーションは**下タブ固定**。上部は情報表示に使う。
- `standalone` 起動時のノッチ／ホームインジケータは `env(safe-area-inset-*)` で必ず避ける
  （`the-oldman` で一度踏んだ問題。同じ轍は踏まない）。
- 入力欄は `font-size: 16px` 以上（iOS Safari の自動ズームを防ぐ）。電話番号は `inputmode="tel"`。

```
┌─────────────────────┐
│  8/7(金) 通常営業 ●繁忙 │ ← ヘッダー：営業日と営業モードを常時表示
├─────────────────────┤
│                     │
│      コンテンツ       │
│                     │
├─────────────────────┤
│ 今日 予約 暦 集計 設定 │ ← 下タブ（5つ）
└─────────────────────┘
```

## 2-2. 各画面の詳細

### S0. ログイン `/login`

- **役割**：スタッフ個人の認証。
- **要素**：ログインID（メールアドレスではなく短いID）／パスワード／ログインボタン／エラー表示。
- **仕様**：`login_id` はサーバー側でだけ `{login_id}@shipporitei.local` に変換して認証に渡す。この変換規則はクライアントに出さない。
- **注意**：ログイン失敗の理由を具体的に出さない（「IDまたはパスワードが違います」で統一）。連続失敗はレート制限。

### S1. 初回パスワード変更 `/password`

- **役割**：発行された初期パスワードを、本人しか知らないものに変える。
- **要素**：新パスワード／確認入力／8文字以上のバリデーション。
- **仕様**：`profiles.must_change_password = true` の間は**他のどのページにもアクセスできない**（ミドルウェアで強制）。

### S2. 今日 `/`（第一画面・最重要）

開いた瞬間に「今日どうなっているか」が分かること。**スクロールなしで**次の3つが見える。

```
┌───────────────────────────────┐
│ 8/7(金) 通常営業  ●繁忙日        │
│ 予約 7件 / 24名   席 18/36     │  ← ①サマリー
├───────────────────────────────┤
│ 18:00 ┃ 田中様 4名 T1  電話     │
│       ┃ [来店]                 │  ← ②時系列リスト
│ 18:30 ┃ 佐藤様 2名 カウンター LINE│
│ 19:00 ┃ ★席未割当 山本様 6名 P1 │     ★＝要対応が上に立つ
│ 20:00 ┃ 鈴木様 8名 個室  HP(仮) │
├───────────────────────────────┤
│           ＋ 予約を登録          │  ← ③常時見えるFAB
└───────────────────────────────┘
```

- **①サマリー**：予約件数／総人数／席の埋まり具合。**イベント営業日はここが「定員 42/60名・残18」に変わる**。
- **②時系列リスト**：時刻順。1件＝1カード。カードに出すのは
  時刻・お客様名・人数・割当席・流入元バッジ・状態バッジ。タップで S5 へ。
  - カード右のボタンで**その場で「来店(seated)」「会計済(completed)」**にできる（1タップ）。
  - **要対応**（席未割当 / 仮予約のまま当日 / 電話番号なし）は先頭にまとめて出す。
- **③FAB**：どこにいても「＋ 予約を登録」が親指の位置にある。
- 日付は前後にスワイプ／`＜ 今日 ＞` で移動できる（明日の下見が一番多い操作）。

### S3. 予約一覧 `/reservations`

- **役割**：探す。「先週LINEで来た鈴木さんの予約」にたどり着く。
- **要素**：
  - 期間指定（今日 / 今週 / 今月 / カスタム）
  - フィルタ：状態（仮・確定・来店中・完了・キャンセル・no-show）／流入元／席／人数
  - フリーワード検索（お客様名・カナ・電話番号の一部・メモ）
  - 一覧（日付でグルーピング）／件数と人数の合計を常時表示
  - CSV出力（`stats.read` 権限）
- 既定の並びは `biz_date` 昇順→時刻昇順。過去を見るときは降順に切り替え。

### S4. 予約登録 `/reservations/new`

**電話を受けながら、通話中に入力し終える**のが要件。入力順は電話で聞く順に並べる。

| 順 | 項目 | 入力形式 | 必須 |
|---|---|---|---|
| 1 | 日付 | 今日/明日/カレンダー（既定＝今日） | ● |
| 2 | 時刻 | 18:00〜24:00 を30分刻みチップ | ● |
| 3 | 人数 | 1〜10は数字チップ、11名以上はステッパー | ● |
| 4 | お名前 | テキスト（カナは任意） | ● |
| 5 | 電話番号 | `inputmode="tel"` | 電話予約は● |
| 6 | **流入元** | 6択チップ。`オーナー直接`を選ぶとオーナー3名の選択が出る | ● |
| 7 | 席 | 空き席候補から選択（**ルール判定つき**。後回し可） | — |
| 8 | コース/飲み放題 | マスタから選択 | — |
| 9 | メモ | 自由記述（アレルギー・お祝い・領収書の宛名など） | — |

- **流入元は既定値を入れない**。選ばないと保存できない（集計の根幹なので妥協しない）。
- **席選択**は候補ごとに判定を色で出す：
  - 緑「割当可」／黄「席が大きく空きます（warn）」／赤「金土の2名×6人席は原則NG（deny）」
  - 赤を選ぶと **理由の入力欄が開き、書かないと保存できない**。書けば通る。
- **貸切（お店全体）はチェック1つ**（2026-08 追加）。席は1つずつ選ばず、`is_exclusive` と席メモ「貸切」で記録する。
  チェックを入れると席のチップが引っ込み、その日はネット予約も自動で止まる（`hasExclusive` → 満席）。
  すでに他のご予約が入っている日は、確定の直前に件数を出して一度だけ確認を挟む。
  逆に、貸切が入っている日は席のご予約を受けない（画面でも知らせ、サーバー側でも断る）。
- **イベント営業日を選ぶと、席の欄が消えて「残り定員 18名」の表示に変わる**。人数が残り定員を超えると警告。
- **保存後は暦（S1）へ戻る**（店主指示 2026-08-17）。`/?m=YYYY-MM&d=YYYY-MM-DD` で、
  いま入れた日の位置で開くので、入った予約がその行に見える。
  日別に留まると、次の1件を入れるにも別の日を見るにも一度戻る手間がかかる。
  編集（S5から）の保存後は、変えた内容が見える予約詳細に戻る。

### S5. 予約詳細・編集 `/reservations/[id]`

- **役割**：1件の予約の全情報と、当日の操作。
- **要素**：
  - ヘッダー：受付番号（`R-2608-0142`）・状態バッジ・流入元バッジ
  - 内容（S4と同じ項目の編集）
  - **席割り当てパネル**：現在の割当／変更／**複数席の連結**（テーブル2卓で12名など）
    - ルール判定と上書き理由をその場で表示（「8/1 岡が上書き：常連・増員の可能性あり」）
  - 状態遷移ボタン：確定／来店／会計済／キャンセル（理由必須）／no-show
  - 変更履歴（誰がいつ何を変えたか＝`audit_logs` の該当分）
- 削除はしない。キャンセルは状態変更として残す。

### S6. カレンダー `/calendar`

- **役割**：月を俯瞰して、営業モードと繁忙日を管理する。
- **要素**：月グリッド。各日に
  - 営業モードの色（通常＝木目色／イベント＝ビール色／休業＝グレー）
  - 繁忙日マーク（●）
  - 予約人数（例：`24名`）と埋まり具合のバー
- 日をタップ → S7（営業日設定）。長押しで**繁忙日のON/OFFだけを即トグル**（一番多い操作なので1タップに寄せる）。
- 月合計（予約件数・人数・流入元内訳）をフッターに表示。

### S7. 営業日設定 `/calendar/[date]`

- **役割**：**その日をどう営業するか**を決める。このシステムの分岐点。
- **要素**：
  - 営業モード：`通常営業（しっぽり）` / `イベント営業（ビアホール）` のセグメント切替
  - イベント選択時のみ：**イベント名**／**定員（総受け入れ人数）**／備考
  - 繁忙日トグル（席割り当てルールが参照する）
  - 休業トグル（臨時休業。火曜は既定で休業）
  - 営業時間の上書き（既定：日〜木 18:00〜24:00／金土 18:00〜25:00）
  - その日の予約サマリーへのリンク
- **モード変更の安全装置**：すでに席割り当て済みの予約がある日を `event` に切り替えるとき、
  「席の割り当て◯件が解除されます」と確認する（割当は残したまま無効化し、通常に戻せば復活する）。

### S8. 席マップ `/seats`

- **役割**：時間帯ごとの席の埋まり方を1画面で見る。通常営業日のみ。
- **要素**：縦＝席ユニット（カウンター／T1／T2／T3／掘りごたつ個室）、横＝18:00〜25:00 のタイムライン。
  予約が帯で並ぶ。帯をタップで S5 へ。空きをタップで S4（その席・その時刻で登録）へ。
- カウンターは相席（`is_shared`）なので、帯ではなく**残席数の推移**として表示する（10席のうち何席使用中か）。
- 席マスタの編集（席の追加・定員変更・有効/無効）もこの画面から（`settings.write`）。

### S9. 席割り当てルール `/rules`

- **役割**：「金土の2名を6人席に通していいか」を店のルールとして明文化する。
- **要素**：ルール一覧（優先度順）。1件＝
  - 名前／判定（許可・確認・原則NG）／優先度
  - 条件：曜日（複数選択）・繁忙日（問わない/繁忙日のみ/非繁忙日のみ）・席エリア・席定員の範囲・予約人数の範囲・適用期間
  - スタッフに見せるメッセージ
  - 有効/無効トグル
- **プレビュー機能**：「金曜・繁忙日・2名」を入れると、各席に対する判定結果が即座に出る。
  ルールを書いた人が、意図どおりか自分で確かめられる。
- 上書き（override）の実績をルールごとに表示（「このルールは今月12回上書きされています」→ルールを見直す材料）。

### S10. 集計 `/analytics`

- **役割**：流入元別の分析。**依頼の「あとから経路別に集計・分析できるように」への回答**。
- **要素**：
  - 期間指定（今月／先月／今年／カスタム）
  - **流入元別**：予約件数・人数・キャンセル率・no-show率（棒＋表）
  - オーナー直接の内訳（3名それぞれ）
  - 曜日別・時間帯別の人数
  - 営業モード別（通常 vs イベント）の実績
  - 席ごとの稼働率、ルール上書き回数
  - CSV出力
- グラフは軽量な自前SVGで描く（重いチャートライブラリは入れない。iPhoneでの初回表示を優先）。

### S11. 設定 `/settings`

- 店舗の既定値：営業時間（曜日別）／定休日／標準滞在時間（既定120分）／イベント時の既定定員
- コースマスタ（おまかせ宴会コース・二次会セット など。価格・飲み放題有無・最低人数）
- 自分のパスワード変更
- アプリのバージョン／キャッシュ更新

### S12. アカウント管理 `/settings/accounts`（`owner` のみ）

- スタッフ一覧（ログインID・表示名・ロール・状態・最終ログイン）
- 新規発行：表示名とログインIDを入れると**初期パスワードが画面に1度だけ表示される**（口頭で渡す運用）
- ロール変更／停止（`is_active = false`）／パスワード再発行
- 停止したアカウントは即座に読み書きできなくなる（RLSレベルで拒否）

### S13. 監査ログ `/settings/audit`

- 誰が・いつ・どのテーブルの・どの行を・どう変えたか（前後のJSON差分）
- 予約／営業日／ルール／アカウントの変更を対象にする
- 期間・担当者・操作種別で絞り込み

### シフトの時間（2026-08-17 追加）

人ごとに基本の出勤時間を持たせ、◯を押した日に自動で入る。**提出の簡単さは変えない**
（店主指示）——毎日時間を選ばせると、いまの「タップするだけ」の速さが失われるため。

| | 基本の時間 |
|---|---|
| 金本 | 19:30〜LAST |
| 安藤 | 18:00〜20:00（日月は普段お休み） |
| 白石 | 18:30〜LAST |
| 高木 | 19:00〜LAST |
| 安井 | 18:30〜21:00 |
| 店長・オーナー | 時間を持たない（チップに名前だけ出る） |

**LAST は「その日の閉店まで」という意味で持つ。** 金土25:00・それ以外0:00 だが、
これは営業時間そのもの。`end_min = null` を LAST とし、表示するときに
その日の `close_min` を当てる。25:00 と書き込むと、営業時間を変えた日に
シフトだけ古い時刻で残る。

**3つの状態を取り違えないこと**（判定は `src/lib/shift-time.ts` の1か所だけ）:

| 状態 | 持ち方 |
|---|---|
| 時間の概念を持たない人 | `profiles.default_start_min` が null |
| その日は基本のとおり | 行の `start_min` が null（`end_min` も基本に従う） |
| その日だけ違う | 行に時刻が入っている（`end_min` の null は LAST） |

2列を必ず組で読むので、「未設定」と「LAST」を取り違えない。
聞き取った時間そのものを含めて `shift-time.test.ts` の12件で固定してある。

**触った日だけ記録する。** ◯を押しただけの日には何も書き込まない——
基本の時刻を毎回書き込むと、あとで基本を変えたときに古い時刻が残り続け、
どれが本当か分からなくなる。

**どこで直せるか**:
- 提出（スタッフ）… グリッドの下の「時間が違う日を直す」を開く。畳んだ状態から始まる
- 確定（店長）… 本人が直した時間をそのまま引き継ぐ
- 日別画面（店長）… その場で直せる。当日の調整（「その日は20時から」）はここで起きるので、
  月のグリッドに詰め込むより、日を開いて直すほうが指も目も迷わない

**DB関数は引数名を変えた別物として足してある**（`p_dates`→`p_days`、`p_profile_ids`→`p_shifts`）。
旧い形も残っているので、配り替えの途中で古い画面が動いていても提出が壊れない。

### S15. 席ボード `/board`（タブレット常設）

実店舗の配置どおりのフロア図。カウンター10席は丸椅子を1つずつタップ、卓と和室は席ごとにタップ。
新しいネット予約は音つきの全画面お知らせで、タップして確認するまで消えない。

**席は3つの状態を持つ**（店主指示 2026-08-17）：

| 見た目 | 意味 |
|---|---|
| 白 | 空き |
| **点線＋姓** | 予約（まだご来店前）。予約から自動で作った下書き |
| 塗り | 着席（タップして点けた席） |

予約ぶんを開店前に手で並べ直す作業を無くすのが目的。ただし**下書きは正解ではない**——
当日の流れで必ずズレるので、点線を押して実際の席を点ければそれで直る。
着席と同じ見た目にしないのは、「あと何組まだ来ていないか」が画面から読めなくなるため。

**下書きはDBに保存しない。** 保存すると「予約が入っている席」と「本当に座っている席」の
区別がつかなくなる。毎回 `src/lib/seat-plan.ts` が予約から作り直す。

カウンターの案内の法則（店主から聞き取り・`seat-plan.test.ts` で固定）：

| 組の人数 | 案内する順番 |
|---|---|
| 1名 | 3 → 4 → 5（真ん中に寄せ、両端と一角を組のために空ける） |
| 2名 | 1・2 → 6・7 → 3・4（真ん中は最後。先に使うと長い辺が分断される） |
| 3名 | 8・9・10 → 1・2・3 → 5・6・7（折れた先の一角にまとまる） |
| 4名以上 | 10 → 9 → 8 …（角をまたいで続きの席が取れる） |

席メモが未指定の予約は、4名以上なら空いているテーブル、無ければカウンター。3名以下はカウンター。
**和室（個室掘りごたつ）には自動で入れない**——指定して取るお席なので、下書きが埋めると
「空いていないように見える」だけの害になる。卓と和室は対面になる順で座らせる。

入りきらなかった組は席を決めずに残し、画面上部に名指しで出す（黙って落とすと数が合わない）。

**この下書きはネット予約の空き判定にも渡している。**
席メモが「指定なし」の予約は、それまで空き判定に一切数えられていなかった
（`computeSeatUsage` は指定なしを読み飛ばす）。3名の指定なし予約が3組入っていても
ネット予約からはカウンターが10席空いて見え、当日に席が足りなくなる形だった。
下書きで実際の席まで決めることで、そのまま埋まりとして数えられる。

### 売上タブの年間ページ `/sales/year`（2026-08-18 追加）

月ごとの目標と実績を一覧と棒グラフで見る。売上タブ（月）の右上「年間」から開く。

- 棒＝実績（物販こみ）、金の線＝その月の目標。年のナビで前後の年に移れる
- 月をタップするとその月の売上タブへ
- 前年の同じ月の実績も一緒に取り、前年比を出す

**進行中の月に達成率を出さない。** 8月17日に「8月の達成率 61%」と出すと、
月末の姿と混ざって読めない。代わりに「途中（15日）」と、何日ぶんの数字かを出す。

**達成率と前年比は「終わった月だけ」で揃えて比べる。** 8月17日に2026年の8.5か月ぶんを
2025年の12か月ぶんと比べると前年比は −44% になる。数字は正しいが意味が違う——
「負けている」のではなく「まだ4か月ぶん足していない」だけ。
年の合計に出るのは**達成率ではなく「年間目標の進捗」**で、成績は
その下の「1〜7月で見ると…」の行が受け持つ。日毎の画面で同じ間違いを直したのと揃えてある。

**月間は物販こみの合計**（店主指示 2026-08）。日毎の画面が店内だけで見ているのと
足し方が違うので、画面の下にもそう書いてある。

### 客数と客単価（2026-08-18 追加）

エアレジの日別売上には金額の右に「会計数・会計単価・**客数**・客単価」が並んでいる。
週次レポートは前からこれを読んでいたが、予約アプリには金額しか渡していなかった。
`sales_daily` に `guest_count`（客数）と `check_count`（会計数＝おおよその組数）を足し、
取り込みAPI（`/api/sales/ingest`）で一緒に受ける。

**客単価は保存しない。** 割り算は `src/lib/sales.ts` の `perGuest()` の1か所でやる。
平均を保存すると、あとから実績を直したときに置いていかれて必ず食い違う。

**分子と分母は同じ日ぶんに揃える。** 客数が月の半分しか取り込めていない月に、
月まるごとの売上を客数で割ると客単価が倍に見える。売上タブは「客数が入っている日の売上 ÷ 客数」で出し、
足りない月は「※ 客数が取り込めているのは ◯日ぶんです」と画面に書く。

**物販は客単価から抜く**（店主指示 2026-08-18）。太巻きが62万入った日を混ぜるとその月の
客単価だけ跳ね上がり、店の地力が読めなくなる。日毎の売上を店内だけで見ているのと同じ考え方で、
客単価も「（売上 − 物販）÷ 客数」で出す。物販があった月は画面にもそう書く。

ひとつだけ直せない歪みがある。**分母の客数にはお持ち帰りだけのお客様も入っている**
（エアレジの客数がそう数える。税率別に客数は出ないので分けようがない）。
太巻きの日を含む月は、そのぶん客単価がすこし低めに出る。

0 は送らない——「読めなかった日」と「0名だった日」は違う（税率別と同じ考え方）。

過去ぶんは `shippori-report` の `data/sales-daily-history.csv`（date,sales,customers・
2024-01-04〜2026-05-28）に客数が入っているので、`scripts/backfill-actuals.mjs` で流し込める。

### 予約登録の席選びに「いま着席中」を出す（2026-08-18 追加）

飛び込みのお客様には**予約の行が無い**（席ボードで席を点けるだけ）。そのため予約登録・編集画面は
予約だけを見て「T1 空き」と出していた。**同じアプリなのに、タブレットの席ボードと答えが違う**状態。

ネット予約のほうは前から席ボードを見ている（`net_reserve` がDBの中で
`seat_board` を突き合わせる。カウンターは予約とボードの大きい方、卓・和室は
どちらかが埋まっていれば満席）。ずれていたのはスタッフ側だけ。

**印を出すだけで、選べなくはしない。** 選べなくすると、着席済みの予約を直せなくなる——
T1のお客様が着席してボードを点けたあと「1人増えます」で人数を直そうとすると、
埋めているのが本人なのに弾かれる。ボードには予約IDが無いので、自分自身が座っていることを
見分けられない。営業中に人数を直せないほうが、まれな席の取り合いより実害が大きい。

真実は見せて、判断は人に残す——22時からの予約に、いま座っている卓を当てるのは
正しい判断でありうる。

| 見た目 | 意味 |
|---|---|
| ふつう | 空き |
| **枠が朱＋「着席中」** | 席ボードでいま点いている（**選べる**） |
| 灰色・押せない「済」 | その日すでに予約が入っている |

読み取りは `src/lib/seats.ts` の `boardUsage()` の1か所。**空き判定（`computeSeatUsage` /
`isSeatFull`）には混ぜていない**——混ぜた瞬間に上の事故が起きるので、型のコメントにも書いてある。
`seats.test.ts` の6件で固定（0は座っていない／旧'C'と C1〜C10 は大きい方／同じ卓の複数席は1つ）。
