# 2. 画面一覧

## 2-0. 前提：iPhoneの片手操作が基準

- 基準解像度 **375×667（iPhone SE）**。ここに収まらないものは設計が間違っている。
- 主要操作（予約を1件登録する／席を割り当てる／来店にする）は**親指の届く下半分**で完結させる。
- ナビゲーションは**下タブ固定**。上部は情報表示に使う。
- `standalone` 起動時のノッチ／ホームインジケータは `env(safe-area-inset-*)` で必ず避ける
  （`the-oldman` で一度踏んだ問題。同じ轍は踏まない）。
- 入力欄は `font-size: 16px` 以上（iOS Safari の自動ズームを防ぐ）。電話番号は `inputmode="tel"`。

```
┌─────────────────────┐
│  8/7(金) 通常営業 ●繁忙 │ ← ヘッダー：営業日と営業モードを常時表示
├─────────────────────┤
│                     │
│      コンテンツ       │
│                     │
├─────────────────────┤
│ 今日 予約 暦 集計 設定 │ ← 下タブ（5つ）
└─────────────────────┘
```

## 2-2. 各画面の詳細

### S0. ログイン `/login`

- **役割**：スタッフ個人の認証。
- **要素**：ログインID（メールアドレスではなく短いID）／パスワード／ログインボタン／エラー表示。
- **仕様**：`login_id` はサーバー側でだけ `{login_id}@shipporitei.local` に変換して認証に渡す。この変換規則はクライアントに出さない。
- **注意**：ログイン失敗の理由を具体的に出さない（「IDまたはパスワードが違います」で統一）。連続失敗はレート制限。

### S1. 初回パスワード変更 `/password`

- **役割**：発行された初期パスワードを、本人しか知らないものに変える。
- **要素**：新パスワード／確認入力／8文字以上のバリデーション。
- **仕様**：`profiles.must_change_password = true` の間は**他のどのページにもアクセスできない**（ミドルウェアで強制）。

### S2. 今日 `/`（第一画面・最重要）

開いた瞬間に「今日どうなっているか」が分かること。**スクロールなしで**次の3つが見える。

```
┌───────────────────────────────┐
│ 8/7(金) 通常営業  ●繁忙日        │
│ 予約 7件 / 24名   席 18/36     │  ← ①サマリー
├───────────────────────────────┤
│ 18:00 ┃ 田中様 4名 T1  電話     │
│       ┃ [来店]                 │  ← ②時系列リスト
│ 18:30 ┃ 佐藤様 2名 カウンター LINE│
│ 19:00 ┃ ★席未割当 山本様 6名 P1 │     ★＝要対応が上に立つ
│ 20:00 ┃ 鈴木様 8名 個室  HP(仮) │
├───────────────────────────────┤
│           ＋ 予約を登録          │  ← ③常時見えるFAB
└───────────────────────────────┘
```

- **①サマリー**：予約件数／総人数／席の埋まり具合。**イベント営業日はここが「定員 42/60名・残18」に変わる**。
- **②時系列リスト**：時刻順。1件＝1カード。カードに出すのは
  時刻・お客様名・人数・割当席・流入元バッジ・状態バッジ。タップで S5 へ。
  - カード右のボタンで**その場で「来店(seated)」「会計済(completed)」**にできる（1タップ）。
  - **要対応**（席未割当 / 仮予約のまま当日 / 電話番号なし）は先頭にまとめて出す。
- **③FAB**：どこにいても「＋ 予約を登録」が親指の位置にある。
- 日付は前後にスワイプ／`＜ 今日 ＞` で移動できる（明日の下見が一番多い操作）。

### S3. 予約一覧 `/reservations`

- **役割**：探す。「先週LINEで来た鈴木さんの予約」にたどり着く。
- **要素**：
  - 期間指定（今日 / 今週 / 今月 / カスタム）
  - フィルタ：状態（仮・確定・来店中・完了・キャンセル・no-show）／流入元／席／人数
  - フリーワード検索（お客様名・カナ・電話番号の一部・メモ）
  - 一覧（日付でグルーピング）／件数と人数の合計を常時表示
  - CSV出力（`stats.read` 権限）
- 既定の並びは `biz_date` 昇順→時刻昇順。過去を見るときは降順に切り替え。

### S4. 予約登録 `/reservations/new`

**電話を受けながら、通話中に入力し終える**のが要件。入力順は電話で聞く順に並べる。

| 順 | 項目 | 入力形式 | 必須 |
|---|---|---|---|
| 1 | 日付 | 今日/明日/カレンダー（既定＝今日） | ● |
| 2 | 時刻 | 18:00〜24:00 を30分刻みチップ | ● |
| 3 | 人数 | 1〜10は数字チップ、11名以上はステッパー | ● |
| 4 | お名前 | テキスト（カナは任意） | ● |
| 5 | 電話番号 | `inputmode="tel"` | 電話予約は● |
| 6 | **流入元** | 6択チップ。`オーナー直接`を選ぶとオーナー3名の選択が出る | ● |
| 7 | 席 | 空き席候補から選択（**ルール判定つき**。後回し可） | — |
| 8 | コース/飲み放題 | マスタから選択 | — |
| 9 | メモ | 自由記述（アレルギー・お祝い・領収書の宛名など） | — |

- **流入元は既定値を入れない**。選ばないと保存できない（集計の根幹なので妥協しない）。
- **席選択**は候補ごとに判定を色で出す：
  - 緑「割当可」／黄「席が大きく空きます（warn）」／赤「金土の2名×6人席は原則NG（deny）」
  - 赤を選ぶと **理由の入力欄が開き、書かないと保存できない**。書けば通る。
- **イベント営業日を選ぶと、席の欄が消えて「残り定員 18名」の表示に変わる**。人数が残り定員を超えると警告。
- 保存後は S2（今日）または元の日付に戻る。連続登録用に「続けて登録」も置く。

### S5. 予約詳細・編集 `/reservations/[id]`

- **役割**：1件の予約の全情報と、当日の操作。
- **要素**：
  - ヘッダー：受付番号（`R-2608-0142`）・状態バッジ・流入元バッジ
  - 内容（S4と同じ項目の編集）
  - **席割り当てパネル**：現在の割当／変更／**複数席の連結**（テーブル2卓で12名など）
    - ルール判定と上書き理由をその場で表示（「8/1 岡が上書き：常連・増員の可能性あり」）
  - 状態遷移ボタン：確定／来店／会計済／キャンセル（理由必須）／no-show
  - 変更履歴（誰がいつ何を変えたか＝`audit_logs` の該当分）
- 削除はしない。キャンセルは状態変更として残す。

### S6. カレンダー `/calendar`

- **役割**：月を俯瞰して、営業モードと繁忙日を管理する。
- **要素**：月グリッド。各日に
  - 営業モードの色（通常＝木目色／イベント＝ビール色／休業＝グレー）
  - 繁忙日マーク（●）
  - 予約人数（例：`24名`）と埋まり具合のバー
- 日をタップ → S7（営業日設定）。長押しで**繁忙日のON/OFFだけを即トグル**（一番多い操作なので1タップに寄せる）。
- 月合計（予約件数・人数・流入元内訳）をフッターに表示。

### S7. 営業日設定 `/calendar/[date]`

- **役割**：**その日をどう営業するか**を決める。このシステムの分岐点。
- **要素**：
  - 営業モード：`通常営業（しっぽり）` / `イベント営業（ビアホール）` のセグメント切替
  - イベント選択時のみ：**イベント名**／**定員（総受け入れ人数）**／備考
  - 繁忙日トグル（席割り当てルールが参照する）
  - 休業トグル（臨時休業。火曜は既定で休業）
  - 営業時間の上書き（既定：日〜木 18:00〜24:00／金土 18:00〜25:00）
  - その日の予約サマリーへのリンク
- **モード変更の安全装置**：すでに席割り当て済みの予約がある日を `event` に切り替えるとき、
  「席の割り当て◯件が解除されます」と確認する（割当は残したまま無効化し、通常に戻せば復活する）。

### S8. 席マップ `/seats`

- **役割**：時間帯ごとの席の埋まり方を1画面で見る。通常営業日のみ。
- **要素**：縦＝席ユニット（カウンター／T1／T2／T3／掘りごたつ個室）、横＝18:00〜25:00 のタイムライン。
  予約が帯で並ぶ。帯をタップで S5 へ。空きをタップで S4（その席・その時刻で登録）へ。
- カウンターは相席（`is_shared`）なので、帯ではなく**残席数の推移**として表示する（10席のうち何席使用中か）。
- 席マスタの編集（席の追加・定員変更・有効/無効）もこの画面から（`settings.write`）。

### S9. 席割り当てルール `/rules`

- **役割**：「金土の2名を6人席に通していいか」を店のルールとして明文化する。
- **要素**：ルール一覧（優先度順）。1件＝
  - 名前／判定（許可・確認・原則NG）／優先度
  - 条件：曜日（複数選択）・繁忙日（問わない/繁忙日のみ/非繁忙日のみ）・席エリア・席定員の範囲・予約人数の範囲・適用期間
  - スタッフに見せるメッセージ
  - 有効/無効トグル
- **プレビュー機能**：「金曜・繁忙日・2名」を入れると、各席に対する判定結果が即座に出る。
  ルールを書いた人が、意図どおりか自分で確かめられる。
- 上書き（override）の実績をルールごとに表示（「このルールは今月12回上書きされています」→ルールを見直す材料）。

### S10. 集計 `/analytics`

- **役割**：流入元別の分析。**依頼の「あとから経路別に集計・分析できるように」への回答**。
- **要素**：
  - 期間指定（今月／先月／今年／カスタム）
  - **流入元別**：予約件数・人数・キャンセル率・no-show率（棒＋表）
  - オーナー直接の内訳（3名それぞれ）
  - 曜日別・時間帯別の人数
  - 営業モード別（通常 vs イベント）の実績
  - 席ごとの稼働率、ルール上書き回数
  - CSV出力
- グラフは軽量な自前SVGで描く（重いチャートライブラリは入れない。iPhoneでの初回表示を優先）。

### S11. 設定 `/settings`

- 店舗の既定値：営業時間（曜日別）／定休日／標準滞在時間（既定120分）／イベント時の既定定員
- コースマスタ（おまかせ宴会コース・二次会セット など。価格・飲み放題有無・最低人数）
- 自分のパスワード変更
- アプリのバージョン／キャッシュ更新

### S12. アカウント管理 `/settings/accounts`（`owner` のみ）

- スタッフ一覧（ログインID・表示名・ロール・状態・最終ログイン）
- 新規発行：表示名とログインIDを入れると**初期パスワードが画面に1度だけ表示される**（口頭で渡す運用）
- ロール変更／停止（`is_active = false`）／パスワード再発行
- 停止したアカウントは即座に読み書きできなくなる（RLSレベルで拒否）

### S13. 監査ログ `/settings/audit`

- 誰が・いつ・どのテーブルの・どの行を・どう変えたか（前後のJSON差分）
- 予約／営業日／ルール／アカウントの変更を対象にする
- 期間・担当者・操作種別で絞り込み

### S14. 受信箱 `/inbox`（Phase 5）

- LINE公式アカウント等から自動受信したメッセージの一覧
- 1件を選んで「予約にする」→ S4 に本文・送信者名が転記された状態で開く
- 対応済み／無視 のマークで既読管理

## 2-3. 公開画面（既存サイト側）

### P1. 予約フォーム `shipporitei.jp/reserve`

既存Astroサイトに**静的ページとして**追加し、送信先だけ予約管理アプリのAPIに向ける。
既存サイトのデザイン（濃紺×木目）をそのまま使えるので、お客様から見て違和感がない。

- 入力：ご希望日／時刻／人数／お名前／カナ／電話番号／ご要望（アレルギー・お祝い等）
- スパム対策：Cloudflare Turnstile（無料）＋ ハニーポット ＋ IPレート制限
- 送信すると `status = tentative`, `source = web_form` で登録され、**受付番号**が返る
- 画面には必ず「**この時点ではご予約は確定しておりません。折り返しご連絡いたします。**」と明記する
  （席の自動確保はしない。イベント日は「イベント営業日です」の案内を出す）
- 既存の `Reservation.astro`（電話・LINE・Instagram）はそのまま残し、**4つ目の導線として並べる**

### P2. 送信完了 `shipporitei.jp/reserve/thanks`

- 受付番号・入力内容の控え・電話番号（当日は電話が確実である旨）
